# Visual Report Layout Rules

本文件解决的不是“组件长什么样”，而是“模块该怎么排”。

生成可视化报告前，先判断内容结构，再选择页面骨架。不要先决定双栏，再把内容硬塞进去。

## 1. 先判断内容类型

### A. 数据密集型

特征：
- 有明确数字、指标、渠道、占比、趋势
- 图表和表格是主信息

优先骨架：
- 数据驾驶舱版

不适合：
- 大段叙事双栏

### B. 叙事复盘型

特征：
- 重点是过程、方法、结论、问题、下一步
- 信息以段落、要点、流程步骤为主

优先骨架：
- 纵向叙事版

不适合：
- 左边短表格，右边长流程卡的强行双栏

### C. 对比决策型

特征：
- 核心是 A/B、方案一/方案二、流程对比、优劣对照
- 往往会有对比表、对照卡、优缺点清单

优先骨架：
- 对比区全宽
- 下方再接建议、步骤或结论区

不适合：
- 让一个很短的对比表占左半屏，右边放整列高模块

### D. 卡片展示型

特征：
- 有很多相对平级的亮点、单品、案例、模块
- 更适合矩阵展示

优先骨架：
- 卡片矩阵版

## 2. 骨架选择规则

### 纵向叙事版

适合：
- 方法复盘
- 工作流总结
- 会议纪要
- 策略说明

推荐结构：

```text
标题 + 核心结论
↓
全宽对比 / 全宽摘要
↓
流程 / 方法 / 关键收获
↓
问题 / 风险 / 下一步
```

使用条件：
- 文本与结论比图表更重要
- 左右模块很难做到高度平衡

### 平衡双栏版

适合：
- 两组信息量接近的模块
- 左右都可以独立成块

推荐结构：

```text
左栏：图表组 / 卡片组 / 丰富摘要
右栏：图表组 / 卡片组 / 丰富摘要
```

使用条件：
- 左右信息量接近
- 左右预计高度接近

禁止条件：
- 一边只有 2 行摘要
- 一边是短表格，另一边是 4 张步骤卡
- 一边只有一个小模块，另一边是高密度内容堆叠

### 数据驾驶舱版

适合：
- 销售复盘
- 经营汇报
- 渠道分析

推荐结构：

```text
标题 + 核心结论
↓
KPI 卡片
↓
图表双栏
↓
数据表格
↓
洞察 / 建议
```

### 卡片矩阵版

适合：
- 单品突破
- 亮点总结
- 模块展示

推荐结构：

```text
标题
↓
卡片矩阵（2x2 / 3x2）
↓
补充说明 / 结论
```

## 3. 反留白硬规则

### 规则 1

短表格（2-3 行）不要单独占据一整列。

替代方式：
- 改为全宽对比表
- 拆成 2-4 张对比卡
- 和摘要卡合并成同一个模块

### 规则 2

4 步以上流程卡，不要和一个短模块左右并排。

替代方式：
- 流程卡改为全宽
- 或把另一侧扩展成同等密度的“关键结论卡组”

### 规则 3

如果你预估某一侧高度明显比另一侧短很多，必须改布局。

可选动作：
- 改成上下结构
- 把短模块拆分并补充摘要/洞察/结论卡
- 把较短模块并入其他 section

### 规则 4

一块区域的“信息量”和“占地面积”要匹配。

示例：
- 1 个短结论 = 不应占半屏
- 2 行表格 = 不应撑一整列
- 单图表 = 可与单图表或卡片组并排

## 4. 模块配对矩阵

### 适合并排

- 图表 + 图表
- 图表组 + 卡片组
- 卡片组 + 卡片组
- 丰富摘要 + 流程卡（前提是两边高度接近）
- 表格 + 表格（前提是规模接近）

### 不适合并排

- 短表格 + 长流程卡
- 单段摘要 + 多卡片堆栈
- 2 行结论 + 大图表组
- 单一图标指标 + 大段说明

## 5. 典型场景建议

### 场景：方法复盘 / AI 协作流程总结

推荐：

```text
标题 + 核心结论
↓
全宽对比区
↓
全宽推荐执行链路
↓
关键收获卡片矩阵
↓
问题 / 下一步双栏
```

不推荐：

```text
左：短对比表
右：4 步执行链路
```

原因：
- 左右高度天然失衡
- 左侧容易出现大块留白

### 场景：经营复盘 / 销售复盘

推荐：

```text
KPI 卡片
↓
图表双栏
↓
全宽数据表
↓
品类 / 单品 / 建议
```

### 场景：亮点型汇报

推荐：

```text
标题
↓
3-6 张亮点卡片
↓
补充图表或建议
```

## 6. 生成前快速检查

在真正写 HTML 前，快速过一遍：

- 这个页面最重要的信息是什么？
- 它更像对比、叙事、数据，还是展示？
- 有没有哪个模块明显太短，却占了太大面积？
- 左右模块高度是否大致平衡？
- 如果把某个 section 改成全宽，会不会更合理？

如果任一答案说明版式不平衡，就先重排，再写 HTML。
